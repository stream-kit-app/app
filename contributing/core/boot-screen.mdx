# Boot screen

Stream Kit shows a boot screen while the app initializes. The implementation uses a two-phase pattern so the splash is visible from the first paint, before JavaScript loads.

## Phases

### 1. Static HTML splash (`app.html`)

`#boot-splash` in [`packages/app/src/app.html`](../../packages/app/src/app.html) renders immediately when the HTML document is parsed. It includes:

- Dark brand background (`oklch(0.06 0.004 264)`)
- Grid overlay
- Logo (`/logo.svg` from `static/`)
- Animated loading bar
- Static "Loading…" label (i18n is not available yet)

Critical CSS is inlined in the `<head>` so no external stylesheet request is needed.

### 2. Svelte `BootScreen` component

Once SvelteKit hydrates, [`BootScreen`](../../packages/app/src/lib/components/core/boot/boot-screen.svelte) in the root layout takes over. It provides:

- Translated strings via i18n
- Boot error display and retry
- Fade-out when `isAppReady` becomes true

The static splash is removed only after `BootScreen` has mounted and painted, using `tick()` plus `requestAnimationFrame` in [`+layout.svelte`](../../packages/app/src/routes/+layout.svelte).

## Tauri window background

The main window in [`tauri.conf.json`](../../packages/app/src-tauri/tauri.conf.json) sets `backgroundColor` to `#0f0f12` so the native window matches the splash before the WebView loads content. This avoids a black flash during dev-server startup.

## Boot sequence

`bootApp()` in [`boot-app.ts`](../../packages/app/src/lib/core/boot-app.ts) runs when the layout loads:

1. Initialize database
2. Register and load plugins
3. Run migrations
4. Boot plugins and load actions
5. Emit app started lifecycle event
6. Load settings

`isAppReady` is set to `true` when this completes. On failure, `bootError` is set and `BootScreen` shows the error with a reload retry.

## Window reveal

In production (`dev` is false), the main window starts small (480×200, frameless, centered, no native shadow) in [`tauri.conf.json`](../../packages/app/src-tauri/tauri.conf.json) to match the boot screen. On Windows, an undecorated window with `shadow: true` draws a 1px border artifact — `shadow: false` avoids that during boot. `centerBootWindow()` also calls `setShadow(false)` on layout mount.

When boot completes, [`revealMainWindow`](../../packages/app/src/lib/core/window/animate-window-size.ts) re-centers the window and animates the resize from that center point. The window stays frameless (`decorations: false`). After the resize finishes, `enableMainWindowPresentation()` turns the native shadow back on (Windows 11 also applies rounded window corners). The `app-window-ready` class on `<html>` clips the webview content to the same corner radius.

In development (`dev` is true), all of this is skipped. `revealMainWindow()` only snaps the Tauri window to the main size with decorations enabled so `tauri dev` stays usable. There is no resize animation, centering, shadow toggling, or rounded-window CSS.

Required Tauri capabilities: `core:window:allow-inner-size`, `core:window:allow-center`, plus existing size and decoration permissions.

## Maintaining visual parity

When changing the boot screen design, update both:

- Inline styles and markup in `app.html` (`#boot-splash`)
- `BootScreen` component styles and layout

Keep class names and dimensions aligned (grid, bar width, logo size) so the handoff from static HTML to Svelte is seamless.
